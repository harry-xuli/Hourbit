# Hourbit 0.2.2 提醒可靠性与安装数据设计

**日期：** 2026-08-09

**目标版本：** 0.2.2

**产品名称：** Hourbit 日程

## 目标

本版本修复真实使用中暴露的重复规则、提醒投递、状态刷新、历史删除、安装命名与数据隔离问题。核心结果是：用户能够确认重复提醒已经创建，到点至少看到应用内提醒，修改或删除到期事项立即生效；新用户得到空数据库，而既有用户升级时数据不丢失。

PDF 报告和后续 Task 6/Task 7 不属于本版本范围，继续暂停。

## 已确认的现状

- `每天`、`工作日（周一至周五）` 和 `每周` 已有领域模型，但每周编辑界面使用自由文本，用户容易把“每周日期”理解为具体日期，而且非法输入会暴露内部参数异常。
- 时间线把任何 `DueAt < now` 且仍为 `Scheduled` 的提醒直接显示为“已错过”，这会掩盖通知投递失败。
- 已打包的安装版与免安装版不包含 `moment.db`、设置文件或测试记录。当前机器看到的旧事项来自 `%LocalAppData%\Moment\data\moment.db`。
- 新安装目录仍硬编码为 `%LocalAppData%\Programs\Moment`，尽管发布程序已经是 `Hourbit.exe`。
- 数据库软删除用于历史与报表保留，但用户界面必须让已错过、已触发等事项正常删除并立即从时间线消失。

## 快速输入时间规则

所有快速输入继续使用本地时区和 24 小时显示。

- 当前为 15:00 时，输入 `5点提醒我按时吃饭`，解释为下一次可到达的 05:00，即次日 05:00。
- 输入 `下午5点提醒我按时吃饭`，解释为 17:00；若当天 17:00 尚未到，则为当天 17:00，否则为次日 17:00。
- `早上5点`、`上午5点` 与 `05:00` 等价。
- 解析后的标题移除被识别的时间短语，但保留其他正文。
- 上述规则必须有固定时钟与本地时区测试，防止以后回归。

## 重复规则

### 用户界面

重复下拉框保留以下四项：

- 不重复
- 每天
- 工作日（周一至周五）
- 每周

选择“每周”后，不再显示自由文本“每周日期”，而是显示周一至周日七个可键盘操作、可由读屏识别的多选控件。至少选择一天才能保存。错误提示使用产品语言，例如“请至少选择一个星期”，不得显示 `ArgumentOutOfRangeException` 或参数名。

`每天` 与 `工作日` 不要求额外输入；编辑已有规则时必须准确恢复选择状态。

### 下一次计划

每个重复系列始终保持一个可观察的下一次已排程 occurrence：

- 创建或编辑系列后立即计算并保存下一次时间。
- 当前 occurrence 到点进入待处理状态时，在同一事务边界内生成下一次 occurrence，不等待用户完成、忽略或稍后提醒。
- 时间线显示重复标签和“下次：yyyy-MM-dd HH:mm”。
- 未来 14 天计划统计包含范围内的下一次重复 occurrence，因此用户创建后能立即确认设置成功。
- 同一系列、同一到期时间只允许一个有效 occurrence，避免刷新或重启产生重复提醒。

本版本不预生成无限历史，也不把未来 14 天内的每一天全部实体化；只保证当前待处理项与下一次计划同时可见。

## 提醒投递与状态机

### 投递渠道

到期时优先显示 Hourbit 应用内提醒窗口。Windows 通知作为辅助渠道，不得成为唯一可见提醒。普通提醒和重要提醒均必须经过可测试的应用内 presenter；重要提醒继续使用声音和置顶策略。

只有至少一个可见渠道成功接受提醒后，occurrence 才进入 `Fired`。如果应用内窗口和 Windows 通知都失败，记录可诊断错误并进入可重试状态，不能伪装成已经提醒。

### 用户可见状态

- `等待中`：未来的已排程提醒。
- `等待处理`：提醒窗口已经成功显示，用户尚未完成、忽略或稍后提醒。
- `提醒失败`：到期但可见渠道投递失败；调度器在有限退避内重试，界面提供“立即重试”。
- `已错过`：应用启动或系统恢复时发现提醒从未成功投递，并且已经超过恢复宽限窗口。
- `已完成` / `已忽略` / `已推迟`：由明确用户动作产生。

时间线不得再用 `DueAt < now` 推导“已错过”，必须显示数据库中的明确状态。宽限窗口沿用恢复服务的统一配置，调度器、恢复服务和界面不得各自定义不同阈值。

## 编辑、删除与刷新

- 将 `等待处理`、`提醒失败` 或 `已错过`事项修改到未来时间时，保存操作把该 occurrence 重置为 `Scheduled`，清空旧处理时间和投递错误，并通知调度器重新排程。
- 保存成功后编辑窗口关闭，时间线立即重新加载。刷新失败时保留现有“仅重试刷新”终态，不重复写入数据库。
- 主时间线增加一个带文字与自动化名称的“刷新”按钮；窗口激活、系统恢复、保存、删除和提醒状态变化仍自动刷新。
- `Scheduled`、`Fired`、`Missed` 和投递失败状态均可删除。重复提醒删除时继续要求选择“仅本次”或“本次及以后”。
- 删除采用现有软删除机制以保留报表历史，但删除后必须立刻从运行时间线、调度器和统计中消失；重复点击删除保持幂等。

## 安装命名与兼容身份

### 新安装

- 默认目录：`%LocalAppData%\Programs\Hourbit`
- 主程序：`Hourbit.exe`
- 开始菜单、桌面快捷方式、卸载项与启动项显示 `Hourbit` / `Hourbit 日程`
- 发布文件继续为 `Hourbit-Setup-x64.exe` 与 `Hourbit-Portable-x64.zip`

### 既有用户升级

- 保留原 Inno Setup `AppId`，让 0.2.2 被识别为原应用的升级。
- 允许 Inno Setup 使用已有安装目录；已经安装在 `Programs\Moment` 的用户不会被强制移动文件夹。
- 精确迁移旧 `Moment` 启动项到新的 `Hourbit` 启动项，只有命中已知旧可执行文件路径时才删除旧值。
- 内部程序集命名和 `%LocalAppData%\Moment\data\moment.db` 在 0.2.2 继续作为兼容身份，不做危险的数据目录搬迁。

## 数据策略

### 首次安装

安装介质不得包含数据库、设置、备份、测试 fixture 或用户记录。若兼容数据目录不存在，应用创建全新的空 schema v4 数据库。

### 升级

安装和升级永不自动删除 `%LocalAppData%\Moment`。迁移在事务中完成，失败时保持原数据可恢复。现有提醒、待办、操作历史和设置全部保留。

### 用户主动重置

设置页增加“重置为全新状态”：

1. 显示将删除提醒、待办、历史和本机设置的明确说明。
2. 要求用户输入确认词或进行第二次确认。
3. 在删除前自动生成一份带时间戳的 `.moment-backup` 到用户选择的位置；用户取消保存则不重置。
4. 安全关闭调度器和数据库连接，替换为新的空数据库并重新启动应用。
5. 任一步失败都保留原数据库，并显示可操作错误。

卸载默认仍保留数据，避免用户误以为普通卸载会删除客户资料。需要清空时使用应用内重置功能。

## 错误处理与诊断

- 所有输入错误转换为中文、字段级提示。
- 通知投递失败记录渠道、异常类型和 occurrence ID，但日志不得包含用户完整正文。
- 刷新失败与持久化失败分开处理，避免重复创建、重复删除或重复通知。
- 调度器重试有次数和退避上限，防止无限循环。

## 验收测试

### Core / Infrastructure

- `5点` 与 `下午5点` 在固定 15:00 时钟下的日期和时间。
- 每天、工作日、单日/多日每周规则的下一次 occurrence。
- 到点后同一事务生成唯一下一次 occurrence。
- 投递成功、双渠道失败、重试成功、系统恢复后真正错过的状态转换。
- 编辑 Fired/Missed/失败 occurrence 到未来后重新排程。
- 删除各种状态及重复范围，运行查询与统计排除软删除记录。

### WPF

- 七个星期多选控件的鼠标、键盘、焦点和 UIA 名称。
- 非法每周选择显示中文提示，不泄露异常。
- 重复标签、下一次时间、刷新按钮和提醒失败操作可见。
- 保存、删除、刷新后真实控件立即更新。

### Installer / Release

- 全新安装目录与所有用户可见名称为 Hourbit。
- 已有 Moment 安装原地升级并保留数据库和设置。
- 安装版与便携 ZIP 均不含数据库或用户数据。
- 便携模式仅在自身 `Data` 目录创建新库。
- 重置失败不损坏原库，成功后为空库且备份可恢复。
- 最终 Release 全量测试、安装脚本静态验证、便携 smoke、安装包 smoke 和 SHA-256 校验全部通过后才能发布 0.2.2。

## 不做的事情

- 不自动信任个人自签名证书，也不绕过 Windows Security 或 SmartScreen。
- 不在升级、卸载或首次启动时静默删除既有数据。
- 不在本版本恢复 PDF 报告开发。
- 不迁移内部命名空间或兼容数据目录；这些变更风险高且与本次用户问题无关。
