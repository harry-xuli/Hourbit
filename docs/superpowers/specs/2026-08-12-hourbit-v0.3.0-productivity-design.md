# Hourbit v0.3.0 生产力与交互完善设计

日期：2026-08-12
状态：用户设计批准，等待书面规格复核

## 1. 目标与发布基线

Hourbit v0.3.0 以当前未发布的 `codex/hourbit-v0.2.2` 修复分支为基线，完整继承其 schema v5、可靠提醒投递、失败重试、每周星期选择器、状态真实性、编辑重排、刷新按钮、Hourbit 安装目录和无用户数据打包等修复。

本次发布同时完成：

1. 待办窄屏可读性；
2. 提醒与待办复制；
3. 通知动作后的自动刷新；
4. 动态倒计时显示；
5. 应用内使用说明；
6. 单一真实进度文档和 GitHub 发布同步。

版本号为 `0.3.0`，Git 标签和 Release 名称为 `v0.3.0`。发布日期在最终发布当天写入 `Version.props`，不得沿用旧日期。

## 3. 待办窄屏布局

### 3.1 可见结构

采用用户确认的方案 B。待办行从左到右显示：

1. 状态图标；
2. 主题标题；
3. 重要性。

主列表不再显示日期或“无日期”文字。标题列使用剩余宽度并拥有最高布局优先级；窗口缩窄时重要性保持紧凑，标题允许字符省略，但不能被固定列完全挤没。

### 3.2 日期与可访问性

- 日期仍保存在数据模型中，并在编辑窗口显示。
- 行级 `AutomationProperties.Name` 继续包含日期或“无日期”、重要性和状态，确保读屏用户没有信息损失。
- 逾期待办仍使用状态图标和语义颜色表达，不能只依赖颜色。

## 4. 复制功能

### 4.1 入口

- 主时间线为当前选中项提供 `复制（Ctrl+D）` 按钮。
- Tooltip 为“复制当前事项并创建新记录”。
- `Ctrl+D` 只在真实待办或提醒行获得焦点时执行，不能在帮助按钮、新建按钮或空白区域复制陈旧选择。
- 没有选中事项时命令不可执行。

### 4.2 复制提醒

- 打开“新建提醒副本”窗口，而不是编辑原 occurrence。
- 复制标题、类型、重要性和重复规则。
- 日期默认当前本地日期。
- 时间默认当前系统时间向后取整到下一分钟；例如 15:42:13 默认 15:43。
- 用户可修改标题、日期、时间、重复规则、类型和重要性。
- 保存调用 `IReminderService.CreateAsync`，产生全新 item/occurrence；取消不写入。

### 4.3 复制待办

- 打开“新建待办副本”窗口。
- 复制标题、日期和重要性，但时间保持为空，因此仍为待办。
- 用户可修改标题、日期和重要性；如填写时间，可沿用既有待办转提醒行为。
- 保存调用 `ITodoService.CreateAsync` 或既有明确的新建转换路径；不得复用原 ID。

### 4.4 重试安全

创建成功但时间线刷新失败时，窗口进入已有 refresh-only 状态，只允许重试刷新，不能重复创建副本。

## 5. 通知动作后的自动刷新

### 5.1 触发动作

以下动作成功持久化后必须请求一次统一时间线刷新：

- 普通 Windows 通知：完成、忽略、稍后提醒；
- 重要提醒窗口：完成、忽略、稍后提醒。

### 5.2 刷新规则

- 复用 `TimelineRefreshCoordinator` 或其轻量抽象，不能把 WPF 依赖放入 Core 服务。
- 动作失败时不刷新为成功状态，并保留现有错误处理。
- 刷新失败不能撤销已经成功的提醒动作；错误需要可观察并允许后续手工刷新。
- 主界面隐藏时也更新共享时间线状态；下次显示必须看到最新数据。
- 并发动作刷新须由 coordinator 合并，避免重复查询和陈旧结果覆盖。

## 6. 动态倒计时

### 6.1 显示规则

仅 `ReminderKind.Countdown` 行显示动态剩余时间：

- 少于一小时：`剩余 04:59`；
- 一小时或以上：`剩余 1:04:59`；
- 到达或超过截止时间：`已到时`；
- 不显示负数。

普通闹钟和计划继续显示原有 `HH:mm` 时间。

### 6.2 更新模型

- 使用生命周期受控的每秒 ticker，只更新当前时间线内的倒计时 ViewModel 属性。
- 每次 tick 均以注入的 `IClock.Now` 重新计算，不能简单递减缓存值，以正确处理系统休眠和时间跳变。
- ticker 不查询数据库、不写状态；提醒调度器仍是到期与通知的唯一状态机。
- 窗口关闭或时间线卸载后停止 ticker，避免 DispatcherTimer 泄漏。

## 7. 使用说明界面

### 7.1 入口与生命周期

- 主界面右上角提供可聚焦的 `?` 帮助按钮，AutomationName 为“使用说明”。
- 托盘菜单增加“使用说明”。
- 两个入口打开同一个单实例帮助窗口；重复点击只激活现有窗口，关闭后可重新打开。

### 7.2 内容

帮助窗口至少覆盖：

- 快速创建提醒或无时间待办；
- 中文、数字日期和 24 小时时间示例；
- `5点` 与 `下午5点` 的区别；
- 每天、工作日、每周星期选择；
- 完成、忽略、稍后提醒；
- 复制按钮与 `Ctrl+D`；
- 倒计时创建和剩余时间；
- 安装版与免安装版的数据位置、升级保留数据原则；
- 托盘退出方式。

内容作为应用资源或 XAML 内容随程序打包，不依赖仓库中的 Markdown 文件存在。

## 9. GitHub 与发布流程

- 从包含全部 12 个未发布修复提交的当前分支继续，开发分支命名为 `codex/hourbit-v0.3.0`。
- 普通 Git HTTPS 凭据已经 dry-run 验证可推送；GitHub CLI 登录另行恢复，用于创建 Release 和上传附件。
- 最终推送必须包含 v0.2.2 基线修复及本次 v0.3.0 变更，不得从旧 `origin/main` 重新开发。
- 发布附件：`Hourbit-Setup-x64.exe`、`Hourbit-Portable-x64.zip` 及两个 SHA256 文件。
- 若 Authenticode 仍为 `NotSigned`，Release Notes 必须明确说明，不得宣称已签名。

## 10. 错误处理与数据安全

- 复制永远创建新记录；任何异常不得修改或删除原记录。
- 安装包继续禁止包含数据库、设置或备份文件。
- 升级继续保留原客户数据和历史兼容安装路径。
- 自动刷新不得在动作失败时伪造成功 UI。
- ticker 和帮助窗口异常不得影响提醒调度主循环。

## 11. 测试与验收

### 11.1 自动化测试

- 待办窄宽度下标题真实可见，日期不在可见树但仍在 UIA 名称。
- 复制提醒/待办产生新 ID、不改变原项、默认时间与无时间规则正确、取消不写入、刷新失败不重复创建。
- 普通通知和重要提醒的完成/忽略/稍后提醒成功后各刷新一次，失败不刷新。
- 倒计时 FakeClock/tick 覆盖秒级、小时级、归零、休眠跳变、非倒计时和 Dispose。
- 帮助入口键盘/UIA、单实例、关闭重开、托盘菜单顺序和关键内容。
- 最终完整 Release 测试、发布脚本和 packaged smoke 全部通过。

### 11.2 手工验收

- Windows 11 在窄窗口实际查看待办标题。
- 复制提醒和待办并修改后保存，确认原记录不变。
- 点击真实提醒窗口动作，确认主界面无需手工刷新。
- 观察至少一个 5 分钟倒计时跨分钟和到期。
- 从主界面与托盘打开帮助窗口。
- 安装版升级保留既有数据；免安装 ZIP 首次启动不含历史数据。
