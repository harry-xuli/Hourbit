# Hourbit v0.3.0 Productivity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Hourbit v0.3.0 with immediate post-notification refresh, a compact todo layout, safe reminder/todo duplication, a live countdown, packaged help, truthful progress documentation, and GitHub release artifacts.

**Architecture:** Keep persistence and scheduling in Core/Infrastructure and place UI refresh, window lifetime, keyboard routing, and ticking in Moment.App. Reuse `TimelineRefreshCoordinator` as the single refresh owner, create copies only through new-record service calls, and make countdown text a clock-derived presentation concern with no per-second database traffic.

**Tech Stack:** .NET/WPF, C#, SQLite, xUnit, Windows App SDK notifications, Inno Setup, PowerShell release scripts, GitHub CLI.

## Global Constraints

- Release version is `0.3.0`; Git tag and GitHub Release name are `v0.3.0`.
- The implementation base is the current `codex/hourbit-v0.3.0` branch and must retain every unpublished v0.2.2 reliability commit.
- Keep `%LocalAppData%\Moment\data\moment.db`, Inno AppId, and internal `Moment.*` compatibility identities unchanged.
- Do not resume PDF Task 6, paired export UI, reporting E2E, cloud sync, accounts, online help, or data-reset UI.
- Never package databases, settings, backup files, or test fixtures in Setup/Portable artifacts.
- Copies create new records and never mutate or delete the source record.
- Reminder scheduling remains the only delivery state machine; countdown ticking must not query or write the database.
- If Authenticode remains `NotSigned`, release notes must state that explicitly.
