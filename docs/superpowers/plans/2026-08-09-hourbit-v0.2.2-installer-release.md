# Hourbit 0.2.2 Installer and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give new installations only Hourbit user-visible names while preserving existing Moment installations and customer data during upgrade, then build and publish verified v0.2.2 artifacts.

**Architecture:** Retain the existing Inno AppId and legacy migration identifiers, change defaults and newly written visible identities to Hourbit, and let `UsePreviousAppDir` preserve the old directory for installed upgrades. Build from one version source, validate package hygiene, sign locally with Harry's existing certificate, and publish only after all automated and manual gates pass.

**Tech Stack:** Inno Setup 6, PowerShell 5.1/7, .NET 8 self-contained win-x64 publish, Authenticode, GitHub Releases.

## Global Constraints

- Target version `0.2.2`; release date is the actual build date recorded in `Version.props`.
- New install directory is `%LocalAppData%\Programs\Hourbit`.
- Existing installations may remain in `%LocalAppData%\Programs\Moment`.
- Preserve AppId `{8E5D37F4-A701-4B84-A71E-B7C0A8E46D51}` and `%LocalAppData%\Moment\data\moment.db`.
- Never disable or bypass Windows Security or SmartScreen.
- Never install the self-signed certificate into Trusted Root automatically.
- Use TDD/static validation and make each task a separate commit.
